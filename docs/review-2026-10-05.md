# Review of v0.1.6 (2026-10-05)

Scope: runner entry point, launcher integration, build and packaging scripts,
BIOS dispatch generation, and runtime save persistence. This is a targeted
review, not an exhaustive audit of both upstream submodules.

## P1 - BIOS configuration omitted (fixed)

`scripts/build-runner.ps1` invoked `gba_recompile --bios` without the pinned
`bios/gba_bios.toml`. The resulting table lacked entries including 0x138 (IRQ
return) and 0x300, and lacked full BIOS resume coverage. The published executable
reproduces an interpreter abort at 0x080012A8 after a miss at 0x0800126C, with
Windows reporting 0x40000015. Supplying the config restores the required entries.
The corrected binary completes 1,200 boot frames with zero dispatch misses and
zero interpreted instructions, using the same ROM and BIOS.

## P1 - Packaging accepted untested executables (fixed)

`scripts/package-release.ps1` previously checked file presence only. The earlier
three-frame boot check did not reach the failing transition. Packaging now runs
1,200-frame boot and reload checks on an isolated copy of the staged executable
and DLLs before writing the archive. A missing BIOS now fails the runner build
instead of producing an unsupported HLE build or reusing stale BIOS output.

## P2 - Headless input requires unavailable fallback (open)

The new optional 3,600-frame input test exits without crashing but encounters
missing static entries including 0x08000380 and 0x080C57D0. TCC compilation fails
in an environment containing only packaged DLLs; no compiler is shipped. This
does not prove the same misses occur in interactive play: headless input uses a
different frame-unwind path. Keep this test as a failing coverage diagnostic,
compare with a windowed input replay, and fix static resume coverage before
claiming all gameplay runs fully statically or relying on background compilation.

## P2 - Explicit save overrides still trigger default migration (open)

`src/main.cpp` honors `--save-path` when constructing runtime arguments, but
unconditionally creates and migrates the default executable-local save. A debug
run targeting a disposable save can therefore also modify the default save.
Launcher argument construction also appends a save path unconditionally. Resolve
one effective destination and suppress legacy migration for explicit overrides.
Current release tests avoid this by copying the executable to an isolated folder.

## P2 - Save fallback can delete the last valid save (open)

`extern/gbarecomp/src/runtime/runtime.cpp`, in `flush_save`, falls back from a
failed rename to removing the destination and retrying. If that retry fails, it
also removes the temporary file, potentially losing both versions. Preserve the
old save and the temporary file on replacement failure; fix and test this in the
runtime fork as a separate change with a simulated rename failure.

## P2 - Generator and runtime are not pinned together (open)

`scripts/generate.ps1` defaults to an external GBARecomp executable, while the
runner uses a pinned source submodule. The current generated game table has the
older declaration without `resume`, while the runtime expects it. On this build
the new byte fits zero-initialized padding, so this is not evidence of the
reported crash; it does show missing provenance checks. Generate with a tool
built from the same pin and record that revision before future runtime upgrades.

## Validation boundaries

The corrected executable also completed 600 windowed frames with Direct3D 11
and zero dispatch misses. Boot and SRAM-file reload checks each completed 1,200
frames against the staged archive files. The optional input test remains failing
for the coverage issues above; it is not part of the boot acceptance claim.

Automated SRAM checks verify file creation, size, and reopening, not in-game slot
validity. Full gameplay, rewind, audio, and launcher/controller interaction still
need a user session. The user confirmed a successful test of the corrected
archive before v0.1.7 publication. This confirmation does not establish exhaustive
gameplay coverage. No submodule was modified by this review.
